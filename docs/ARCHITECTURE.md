# BombCat 架构

## 模块边界

项目使用 Python 3.12+ 标准库，界面使用 Tkinter。

```text
main.py / cards.py   界面、卡牌显示、用户选择和对局日志
        │
game_controller.py  数据投影、回合展示与私有选择交互
        │
        ├─ game_core.py   权威规则、观察、合法动作、私有记忆
        │       ▲
        └─ ai_player.py   观察快照、动作校验、主线程提交
                │
          ai_backend.py   Python 子进程、结果队列、任务取消
                │ JSON 行协议
          ai_worker.py    请求校验、预算与结果编码
                │
          search_ai.py    启发式、信息集搜索与模拟
                └─ game_core.py
```

`game_controller.py` 持有实际对局的 `game_core.Game`，把界面操作转换为核心动作并刷新显示。搜索使用同一套规则创建模拟局面。

核心牌堆索引0代表顶部；界面适配层负责显示顺序转换。`revision` 记录每次合法动作，`turn_revision` 记录已完成的一次行动或行动权转移。

## 规则与信息

公开牌组共34张。开局保证的拆除从牌组内发出，双方各6张手牌，剩余22张，上限9张。具体牌组见[规则书](RULEBOOK.md)。

拒绝延迟抵消对手下一张功能牌；攻击转移剩余行动并加一；成功拆弹并放回后结束自己的全部剩余行动。实际对局与模拟统一调用核心校验和结算。

搜索入口只接收不可变的 `Observation`：自己的手牌、对手手牌数量、公共弃牌、已知对手牌，以及合法获得的位置记忆。玩家真实手牌和未知牌堆顺序不进入搜索请求。

私有查看和重排仅更新使用者的记忆。秘密放回炸弹后，对手的位置记忆清空。已知牌被公开打出或消耗时，同步移除相应手牌记忆。

## 搜索

每次迭代从公开库存扣除已知牌，采样一致的对手手牌与牌堆；炸弹不进入模拟手牌。搜索树按根观察者的信息状态区分，对手秘密选择在根视角合并。

树选择使用可用次数修正的 UCB，扩展后通过启发式 rollout 模拟。终局回传胜负，截断局面使用有界资源估值；最终选择访问最多的根动作。重排候选取启发式评分最高的八项。

成功响应包含所选动作、迭代次数、耗时、选择方式和最多三个候选。候选提供访问次数与平均回报；未访问时回报为 `null`，零迭代使用启发式回退。

算法参考 Cowling、Powley、Whitehouse（2012），*Information Set Monte Carlo Tree Search*，DOI `10.1109/TCIAIG.2012.2200894`。[论文存档](https://eprints.whiterose.ac.uk/id/eprint/75048/)。

## 任务与日志

后台搜索使用独立 Python 子进程，不调用 Tk。Tk 主线程通过 `after` 轮询结果，核对对局、任务身份、版本与观察快照后提交动作。

重开和退出会取消搜索并终止对应进程。模态弹窗暂停结果提交；拆弹放回与改变未来分别等待私有选择完成。

调试日志遵循根目录 `AGENTS.md`：决策、局面、搜索统计、各候选与牌堆记忆逐项分行；调试状态保留为内部元数据；卡牌简称复用 `Game._card_short_name`；放回位置从顶部开始、从1计数。

## 验证

`python dev.py test` 运行无窗口测试；`python dev.py check` 执行静态检查。测试覆盖牌数守恒、信息隔离、动作结算、采样、搜索、任务取消、日志与界面控制器。

`python dev.py arena --pairs 4 --iterations 200 --seed 2026` 按成对初始局面交换席位，比较搜索策略与启发式策略。评估与测试均不使用桌面自动化。
